# STYLE / ARCHIVE

Визуальный архив и поисковый индекс художественных стилей (тегов `@artist`) для моделей **AM Preview**, **OPUS** и **SKY**.
Статический сайт без бэкенда. Собирается Vite, выкладывается на хостинг (REG.RU) через GitHub Actions.

## Запуск локально

```bash
npm install            # один раз
npm run dev            # режим разработки, http://localhost:5173
npm run build          # сборка в dist/
npm run preview        # посмотреть собранную версию
```

Для проверки и для выкладки нужен Node 20+ (CI использует 22).

## Структура

```
index.html                 единственная страница (Vite собирает её в dist/)
src/main.js                точка входа: подключает стили и модули
src/css/                   стили (базовый + слои «поверх»; сливаются в рамках Clean Slate)
src/legacy/                прежний код: ядро app.js и модули поверх него (см. docs/INVENTORY.md)
data/                      все данные сайта (JSON)
media/                     картинки (в сборку не входят, едут на хостинг отдельно)
maintenance/index.html     страница-заглушка «технические работы»
tools/                     скрипты обслуживания данных
tests/                     автоматические проверки
docs/                      заметки о состоянии проекта
.github/workflows/         сборка и выкладка на хостинг
```

### Заглушка и открытие сайта

Выкладка по умолчанию ставит на сайт заглушку. Чтобы открыть сайт, в GitHub
(Settings → Secrets and variables → Actions → Variables) создают переменную `SITE_LIVE = 1`
и перезапускают workflow. Перед большим обновлением переменную удаляют, и следующая выкладка
снова ставит заглушку.

### Данные (`data/`)

| Файл | Что это |
|---|---|
| `archives.json` | список архивов и их заявленные счётчики (список архивов и счётчики) |
| `styles.json`, `opus-styles.json`, `sky-styles.json` | записи стилей: `id`, `name`, `presets` (`main`/`alt`), `media`, `published_at` |
| `media.json`, `opus-media.json`, `sky-media.json` | media-id → пути к файлам и размеры. `src` — полный размер (вьювер), `thumb` — миниатюра (сетка) |
| `supported.json`, `opus-supported.json` | полный список имён, которые понимает модель |
| `danbooru.json` | полный экспорт данных Danbooru (**сайт его не грузит**, это исходник для скрипта) |
| `danbooru.min.json` | облегчённая версия, которую грузит сайт. Генерируется `tools/slim_danbooru.py` |

### Медиа (`media/`)

| Папка | Назначение |
|---|---|
| `web/` | AM, полный размер для вьювера (по длинной стороне до 1200 px, WebP) |
| `thumb/` | AM, миниатюры для сетки (560 px по ширине) |
| `opus/`, `sky/` | OPUS и SKY (пока без отдельных миниатюр) |
| `original/` | убрана из рабочего дерева (лимит Pages 1 ГБ). Оригиналы лежат в истории git: `git checkout ccb9ed44 -- media/original` |

## Проверки

Перед каждым релизом (то же самое запускает GitHub Actions на каждый pull request, `.github/workflows/check.yml`):

```bash
python3 tools/audit_data.py        # целостность данных и соответствие схемам (код 1 = есть ошибки)
python3 tests/smoke.py             # соберёт сайт и проверит, что он работает
npm run format:check               # единый стиль кода (npm run format исправит)
```

Один раз: `pip install -r requirements-dev.txt && playwright install chromium`.

При чистке оформления есть попиксельная проверка: `python3 tests/visual.py snap <папка>` до правки, затем после, и
`python3 tests/visual.py diff <до> <после>`: код 1, если хоть один из 34 снимков отличается.

### Схемы данных (`data/schema/`)

`styles`, `media`, `supported`, `archives`: то, что есть сейчас. `mixes`, `events`, `characters`: заготовки под будущие
разделы (данных ещё нет, файл проверяется, как только появится `data/mixes.json` и т. п.).
Схема строгая: неизвестное поле считается ошибкой, поэтому новое поле сначала добавляют в схему.

## Инструменты (`tools/`)

| Скрипт | Что делает |
|---|---|
| `audit_data.py` | проверяет данные: ссылки, файлы, счётчики, дубли |
| `build_thumbs.py` | дорисовывает недостающие миниатюры и прописывает их в `media*.json` (`--archive am\|opus\|sky\|all`) |
| `slim_danbooru.py` | строит `danbooru.min.json` из `danbooru.json` |

## Правила, которые стоит соблюдать

- **`id` стиля не менять и не переиспользовать.** По нему хранится «Saved» у посетителей в браузере.
- Новые изображения всегда сопровождать миниатюрой (`build_thumbs.py`), иначе сетка загрузит полный файл.
- После любой правки данных запускать `audit_data.py`.
- Скрипты `tools/` запускаются из корня репозитория.
