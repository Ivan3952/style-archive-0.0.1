# Как добавлять новые стили (ежемесячное обновление)

Скрипт `tools/import_telegram.py` берёт экспорт Telegram-канала и дописывает новые стили в архив **AM**.
OPUS и SKY пока обновляются вручную: у них другая схема id.

> **Статус правил.** Разбор сверен с реальным экспортом чата «Стили» (166 сообщений, 10.11.2026):
> пересланные посты, подпись у первого сообщения альбома, остальные без текста. Остальные форматы подписей
> появятся по мере экспортов. Первый запуск каждого нового чата делать пробным и сверять отчёт глазами.

## Порядок

1. Telegram Desktop → чат «Стили» → «Export chat history» → формат **JSON**, включить **Photos**.
2. Посмотреть, как разобраны первые посты (ничего не пишет):

   ```bash
   python3 tools/import_telegram.py путь/к/ChatExport --inspect 20
   ```

3. Пробный прогон (ничего не пишет, печатает отчёт):

   ```bash
   python3 tools/import_telegram.py путь/к/ChatExport
   ```

4. Если отчёт верный, записать:

   ```bash
   pip install pillow
   python3 tools/import_telegram.py путь/к/ChatExport --apply
   ```

5. Проверки и коммит:

   ```bash
   python3 tools/audit_data.py
   python3 tests/smoke.py
   git add data media && git commit
   ```

Картинки лежат вне `dist`, поэтому после деплоя кода медиа уходит на хостинг отдельным шагом workflow.

## Что делает скрипт

| Случай в посте | Результат |
| --- | --- |
| `@имя → main`, одно сообщение | одна запись, одна картинка |
| 1 художник, пресет один, k картинок | одна запись с k картинками |
| n художников, пресет один, n картинок | n записей `g<сообщение>-1` … `-n` по одной картинке |
| пресеты `main` и `alt` («мейн/альт», «main \| alt»), 2n картинок | каждому художнику 2 картинки подряд, пресеты в порядке подписи |
| другое соотношение | пост **не импортируется**, раздел «Сомнительные» отчёта |
| нет пресета | не импортируется (арт перегенерируется) |
| стиль с таким названием уже есть | картинки добавляются к старой записи, пресеты объединяются, ставится `updated_at` |

Новые id имеют вид `g<номер сообщения>` (старые числовые id из канала не затрагиваются).
Дата записи — дата сообщения в чате, то есть когда стиль попал в коллекцию.

Повторный запуск безопасен: `data/import_state.json` помнит обработанные посты каждого чата.
Чтобы переимпортировать с нужного места, укажите `--from-id НОМЕР`.

## Проверка самого скрипта

```bash
python3 tests/test_import.py
```

Тест работает на выдуманном экспорте во временной папке, реальные данные не трогает.

## Мешанины (миксы)

```bash
python3 tools/import_mixes.py путь/к/ChatExport            # пробный прогон
python3 tools/import_mixes.py путь/к/ChatExport --show 3   # показать разбор первых миксов
python3 tools/import_mixes.py путь/к/ChatExport --apply    # записать data/mixes.json и картинки
```

Распознаются посты с хештегом `#автор_mixing` (строки с `@художниками` = микс, приветствие и хештег не сохраняются, превью берутся
из сообщений без текста следом) и одиночные генерации из блога с `#ampreview` (микс = токены с `@`).
Веса `(@a:1.4)`, чередование `@[a|(b:1.2)|c]` (поле `group`), теги с весами разбираются; `prompt_raw` хранится дословно.
На сайте миксы появятся в обновлении Foundation, сейчас это только данные.
Тест: `python3 tests/test_mixes.py`.
